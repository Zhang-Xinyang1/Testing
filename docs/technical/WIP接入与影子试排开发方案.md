# WIP 接入与影子试排开发方案

本文保留 2026-11-24 演示预演版的开发方案。后续接入版已实现标准分页采集、MES 工作区增量接收、设备实际释放、外部完工和逐批追溯。真实 MES 字段联调与未来负荷预测仍待现场样本。[接入版运行与验收](WIP现场接入.md)

## 先跑一次客户主线

1. 启动程序，打开“生产看板 · MPS → 演示数据”，载入“客户主线 · 12 Lot”。进入“滚动重排 · 方案”，用影子演示和实际资源试排并选用。月目标 375 片，基线月内预计 220 片。DEMO01-L003 有 25 片，尚无确认的可用时间。
2. 打开“滚动重排 · 方案 → 变化记录”，展开 WIP 来料预演。样例随当前快照生成，数据时点、批次、工序和片数已填好。直接预演可看到同一批次不同工序，以及另一个在制 Lot 的记录如何分别处理。
3. 对比两种证据。先选择“仅预计到达”，预演后可应用数为 0。选择“已确认可用”并再次预演，预期 1 条可应用、2 条仅观察。第一条给出 24 小时后的确定可用时间，后两条不增加可排数量。
4. 应用后回到“试排与比较”，用影子模式重新试排。旧选用方案一直显示至人工选用。候选中 DEMO01 的月预计由 75 片变为 100 片，总预计由 220 片变为 245 片。选用后看板、MPS、甘特和 Lot 查询显示新方案。
5. 查 DEMO01-L003，其第一道工序的资源占用起点应不早于确认时间。再查 DEMO02-L001，其当前机台仍有占用，后续任务为空。“在制待外部预测”的 25 片仍待外部系统提供最终完工信息。

重演可重新载入 basic 场景。上述数字用于这套默认演示规则、资源和来料，现场验收应核对实际任务、机台和片数。

## 参考项目怎样使用 WIP

参考项目 immersion-v2 的读取版本为 44f7f7c。其工序到达数据按 Lot 和工序组织，一个 Lot 在多个工序有多行记录。它把截止时刻之前可到达的 Lot 放入当期候选，按到达顺序、设备资格、片数和负荷分配整批。后续时窗的 WIP 还用于估计设备背景负荷。历史加工记录和预计到达记录对时间、设备的解释不同。

可在对应提交核对实现。[工序到达字段](https://github.com/HawkW1027/immersion-v2/blob/44f7f7c8f5c042d68c7880def7db7728c70eab7f/docs/data_fields_reference.md#L109-L145) · [当期候选筛选](https://github.com/HawkW1027/immersion-v2/blob/44f7f7c8f5c042d68c7880def7db7728c70eab7f/immersion/ga/data_loader.py#L286-L300) · [整批分配](https://github.com/HawkW1027/immersion-v2/blob/44f7f7c8f5c042d68c7880def7db7728c70eab7f/immersion/ga/decoder.py#L120-L156) · [滚动窗口负荷](https://github.com/HawkW1027/immersion-v2/blob/44f7f7c8f5c042d68c7880def7db7728c70eab7f/immersion/ga/fitness.py#L123-L155)

| 可借鉴的做法 | 在测试线上怎样使用 | 适用边界 |
|---|---|---|
| 记录 Lot 到达哪道工序 | 首道可接收工序的确认可用时刻进入 availableAt。其他工序行保留观察结果 | 上游预计到站和排产可用应分别提供。遇到重复访问同名工序需有工序实例 |
| 按片数、按时间窗计算供给 | 经营目标沿用月度 MPS。建议另外按班次汇总已确认待测片数和预计来料片数 | 同一 Lot 在多道工序出现时，库存和最终产出均按同一稳定身份核算 |
| 保留设备资格与实际加工记录 | XMC 继续按 Platform、Recipe、针卡、EQP/Prober 配对及 BAKE 腔体校验 | 上游历史机台、路线中的设备资格都不能证明当前占用哪台 EQP |
| 未来 WIP 用于估算负荷 | 待真实回放稳定后，展示各设备组未来 24/48 小时的预计需求工时，单独列出预计到料部分 | 选择窗口与班次由产线校准。可在多台设备加工的一批货只能分配一次需求量 |

## 当前系统已能处理什么

Excel 的 Lot 明细和可选在制表可组装当前占用。统一快照中的 RUNNING 只保留当前 CP 或 BAKE 腔体的剩余使用时间。排程同时避让 PM、借机、组合资源和冻结任务。DONE 以最后一道加工的实际完成计入当月，RUNNING 只有外部系统提供可信的最终加工结束预测，才有明确的预计产出。静置 336 小时另行展示。

现有接口规范包含设备和 Prober 状态、Recipe 与针卡、产品路线工步、PM 工单。它们可以核对主数据，但缺少哪批货正处在哪道工序、何时可进入测试、占用何时实际释放。PM 标识和 PM 完成时间只属于维护事件。初期保留现有设备、路线和需求接口，单独补充 Lot 级 WIP 事实。

## 本版输入契约和数据流

生产工作区的演示基线 → WIP 记录预演 → 逐行核对 → 应用到新的演示快照 → 影子试排 → 人工选用 → 四个结果视图。预演期间工作区只读；应用在同一事务内写入新快照、报告和变化记录。已选方案继续可查。记录中存在未知 UID、非法工序、重复 UID＋工序或片数不符时，整批返回问题和行号。

| 字段 | 要求与业务含义 |
|---|---|
| snapshotId、asOf | 绑定当前演示基线的版本和采集时点。asOf 要明确到时分，支持带时区日期时间，无时区按北京时间 |
| records[].uid | 必填的稳定字符串批次标识。保留前导零，匹配忽略大小写、全半角和首尾空白。可重复的展示 LotID 不作关联键 |
| step | 必填，匹配该产品路线工序。只有能唯一确认的首道工序可使未知来料具备可排条件 |
| kind | CONFIRMED 表示业务已确认该 Lot 在 at 时刻可供测试。ETA 表示预计到达，只供观察。分类由提供方明确给出 |
| at | CONFIRMED 必填，ETA 可空，精确到时分。确认时刻不晚于 asOf 则 READY，晚于 asOf 则 FUTURE，调度从 at 起才允许使用 |
| wafer、location | 可选。wafer 须为与基线一致的整数，只用于核对。location 是该条报文的上下文，本版不会用预计位置替换当前实际位置 |

演示基线须声明稳定身份。刚新增的物料、已有确定到料时间的改期、HOLD 放行、返工和设备释放，各自需要独立事实；本入口只补已有 FUTURE 批次缺失的可用时间。在制、HOLD、DONE 和属于后续工序的合法来料均保留为观察。新增快照的 wipPilot 留存上一基线编号、确认证据及报告，用于追溯。

| 接口 | 调用与结果 |
|---|---|
| POST /api/production/wip-preview | 直接提交上述报文，读取 report.accepted、rows、errors、applied 和 observed。行结果包括可应用、仅观察、与基线一致、错误、因同批错误跳过。记录级拒绝通过 report.accepted=false 表达 |
| POST /api/production/wip-apply | 提交预演返回的 contextHash 及原 feed。服务端重新核对内容与基线，通过后仅更新演示工作区。输入或基线变化需重新预演。成功请求重试不会重复增加物料或变化记录 |
| POST /api/production/trial、/adopt | 继续使用统一接口。含本次模拟 WIP 的演示快照仅允许 shadow 试排，通过独立校验后由计划员选用 |

## 拿到真实数据后的开发顺序

| 阶段 | 具体工作 | 可交付物和验收条件 |
|---|---|---|
| 1. 对齐原始记录 | 与 MES 对同一 Lot 追踪“Fab 预计 → 可测试确认 → 上机 → 当前工序退出 → 外部终工”。分别记录源时间、采集时间、数量单位、路线版本、工序实例和实际资源。确认全量/增量、撤销及晚到语义 | 签认字段映射和状态字典。每个必填事实均有来源，无法提供的字段有待确认状态。测试样例设计见下表 |
| 2. 只读采集与回放 | 适配真实分页与鉴权。原始报文按来源、批次、读取版本和页码留存。以源事件 ID 和版本去重。先在暂存区拼完整，与现有需求、Lot 库存、设备装配和路线按同一时点核对，再发布完整生产快照 | 同批重放输出一致，缺页或冲突不发布。同一 Lot 多工序只对应一份物料。发生失败时可追到源页和记录，恢复后从确认版本重放 |
| 3. 补齐在机与移交 | 区分到站、实际开工、当前加工结束、设备释放、整 Lot 最终完工。CP 须有实际 EQP、Recipe、针卡。BAKE 须有烤箱、腔体、批次成员、放行时间和占腔结束时间。设计显式“当前占用已释放、后续外部负责”事件及相应状态 | 支持释放当前设备且 Lot 暂无最终完工的情况，测试不重复续排、不提前计产。维护期间整组停机，重叠同腔的不同批次不能共享产能 |
| 4. 影子运行与出货核对 | 同一事实分别生成当前基线和 WIP 候选。每日回放迟到、提前到料、临时 HOLD、延长占用、跨月和迟报完工。计划员逐批核对交期、MPS 及机台冲突 | 两案使用相同的资格和评分。设备重叠、实际完工重复计数、早于确认到料开工均为 0。漏传不释放设备，过期候选无法选用。留存首个可行解时间、总耗时及超时状态，按整月和 30 分钟预算验收 |
| 5. 现场试用 | 基于通过回放的实际快照定时提示变化，计划员试排、确认原因、选用。后续再评估未来班次背景负荷是否提高交期履约 | 可从计划编号追溯数据版本、WIP 证据和操作原因。选用冲突、数据中断和回退演练通过后，再确定开放范围 |

当前系统对曾经 RUNNING、后来缺失或更换工序的 Lot 会阻止排新计划，这能防止占用凭空消失。阶段 3 需要解决一个现场常见情况：当前工序已交给外部，设备确实空闲，但整批尚未终工。现阶段必须保留待核对，不能用 DONE 人为释放。这也是建议先接“可用来料”、再接“实时移交”的原因。BAKE 的加工结束可能早于腔体可用，现场协议必须能表达这两个时间。

## 首批脱敏样本与验收

建议拿 2～3 个连续采集时点，覆盖下列事件。无需先凑几千行。保留相同替代 UID、先后顺序、相对时间、片数及装配关系，便可核对流程。业务正确性按事件覆盖验收，月度耗时另用真实峰值规模的脱敏样本测量。

| 样本 | 应看到的结果 |
|---|---|
| 仅 ETA，随后确认 25 片可用 | 第一版只显示预报。下一版才允许从确认时间安排测试。两版各工序与最终完成可逐批解释 |
| 同一 Lot 两道工序、两个 Lot 同展示号、同工序返工 | 保留同一物料与各工序的区别。两个稳定 UID 分开。无法识别工序访问次数时阻断自动映射 |
| 实际上机且超预计结束，或快照少一行 | 机台/prober 保留占用疑点，等待释放证据。外部最终预测缺失时单列片数 |
| 同腔同批、两批同腔、EQP/Prober 的 PM | 同一 BAKE 批占腔只计一份，超过容量或不同批的冲突拒绝。PM 按现有组合停机规则避让 |
| 已确认来料改期、HOLD 后放行、转外部后最终完工 | 须有可追溯的修订/放行/移交/完工事件。过期预计不得滚入实际完成，实际完成替代该 UID 的预测 |
| 乱序、重复、缺页、旧版选用请求、月末跨零点 | 不回退已确认状态，不部分提交。月内统计按北京时间自然月含月初、不含次月月初 |

需要 MES 和产线共同确认四项：哪个字段可稳定标识 Lot 与单次工序访问；哪个事件表示物料已获准在给定时间进入测试；哪些字段分别证明设备实际释放和最终加工完成；分页、版本和撤销如何保证多次读取能对账。这四项分别决定身份、可排资格、产出和增量重放方式。
