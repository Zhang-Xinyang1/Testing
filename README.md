# XMC 测试排产

读取历史 XLSX，配置机台、在制占用、PM 和借机，比较 Excel MPS 与算法月内完成量。原始 Excel 只读，配置独立保存；排产算法、测试与启动脚本均由 Python 运行，浏览器只负责展示和交互。

## 服务器一键部署

上传整个 Testing 文件夹。Windows 可双击 `一键启动.py`（`.py` 已关联 Python 时）或执行 `py -3 一键启动.py`；macOS/Linux 在终端执行 `python3 一键启动.py`。脚本会先校验后端文件、前端入口与静态资源、Excel 数据和端口，再后台启动服务，并确认 `/api/health`、首页和 `/api/data` 均可用；桌面环境自动打开本机浏览器。启动后访问 `http://服务器IP:8080`。详细说明见 [部署说明](部署说明.md)。需预装 Python 3.9+。

| 操作 | Windows | Linux / macOS |
|---|---|---|
| 启动 | 双击 `一键启动.py` 或 `py -3 一键启动.py` | `python3 一键启动.py` |
| 停止 | 双击 `停止服务.py` 或 `py -3 停止服务.py` | `python3 停止服务.py` |
| 重启 | 双击 `重启服务.py` 或 `py -3 重启服务.py` | `python3 重启服务.py` |
| 状态 | `py -3 deploy.py status` | `python3 deploy.py status` |
| 检查 | `py -3 deploy.py check` | `python3 deploy.py check` |
| 日志 | `py -3 deploy.py logs` | `python3 deploy.py logs` |

Windows 与带图形界面的 Linux/macOS 启动成功会自动打开本机浏览器；SSH/无界面服务器只打印访问地址。前端与 API 由同一个 Python 服务同源提供，排产通过 `POST /api/schedule` 在 Python 后端执行，无需 Node.js、npm 或前端构建。更新后端或配置后请执行重启；只更新前端静态资源时刷新页面即可。关闭启动窗口后服务继续运行，但普通后台模式不保证退出登录或重启后恢复。Linux systemd 开机自启为可选操作，Windows 暂未集成开机自启。

运行依赖清单见 [requirements.txt](requirements.txt)：Python 3.9+，运行时没有第三方包；`python-pptx` 仅作为 PPT 生成工具的可选依赖。

## 开发启动

```bash
python3 run.py
# 打开 http://127.0.0.1:8080
```

请使用后端地址，不是 IDE 的静态 Live Server。静态模式只展示内置数据，不能上传保存，也不执行排产；排产由 Python 后端通过 `/api/schedule` 完成。

## 使用

### 新增：生产工作台（2026-11-12）

左侧“生产工作台 · 新流程”新增 **生产看板、Lot 查询、滚动重排**。先在生产看板载入演示数据，再进入滚动重排试排、比较并人工选用。演示包含已到位、未来来料、日期未知、HOLD、在制和已完工情形，全部为合成数据。页面打开和刷新不排产。

新流程支持内部出货交期优先、借机开始时 Recipe 校验、可配置换 Recipe 30 分钟加换卡 5 分钟、在制仅保留当前占用、14×24h 静置单独展示、三个差额与预警、冻结、异步试排/取消/最多 30 分钟、变化提示、实际资源与扩产假设分开、方案选用与历史比较记录。扩产结果可保存比较，不能选为实际计划。

“滚动重排 → 生产规则与 MES”设置规则并验证完整 JSON 快照。空工作区也可直接接收 MES 快照。定时检查只检查已接收数据并提示变化，MES 主动拉取和计划下发尚未接入。业务字段、单位、状态、限制和接口见 [MES 生产快照要求](docs/technical/MES输入要求_生产快照.md)。

**新规则目前作用于新生产工作台。原 Excel 排程及已有历史保留原规则，输入与结果独立保存。** 实际数据尚未取得，本版先验证功能流程；稳定批次标识与冻结范围仍需产线确认。服务更新后需重启，生产数据在配置目录的 `production/`，升级前请备份。

### 现有 Excel 排程

当前仅使用 `data/Testing调度算例_新版.xlsx`。新版按 2026-11-06 逐项确认、2026-11-09 修订 CP 工时口径的业务规则重建：72 个 PPN、11,000 wafer、三个 CP 机台组、31 个 CP Recipe、62 种针卡类型、119 条借机，7 台 OVEN × 4 腔。MPS 允许同一 PPN 多行（不同厂家或重复订单）；PPN 以第一个 `-` 前为准，`-` 后厂家后缀忽略，读取时按前缀汇总 wafer、合并 Platform，并用前缀匹配 flow.PROD。每 Lot 最多 25 片；没有实际 Lot 明细时默认满 25 片加尾批，当前共 476 Lot。实际 Lot 明细优先；同一 LotID 允许多行，按 LotID 第一个 `-` 前的前缀匹配 flow，`-` 后作为厂家标识不参与路线匹配，每行独立排产。BAKE 每批最多 4 Lot，无额外 wafer 总数限制；升温 2h、加工 24h、降温/换 Lot 2h，占腔 28h，Lot 在第 26h 放行。

规则详见 [业务确认清单](docs/排程业务规则_确认清单.md)。CP 按 RUN 资格及 Platform/TYPE 匹配，路线限定已确认七种模式并保留原表顺序，针卡数量充足、换类型 5 分钟，约束表为禁加工；CP 工时按 `Time`（分钟/wafer）× Lot 实际 wafer 数计算。默认采用多起点与局部搜索，可跨组 Lot 按每道 CP 的兼容资源选择机台；保留原预分组贪心方案作为基线。MPS、月内完成量与各 PPN 达成率均按 wafer 统计；优化目标是各 PPN 月末达成率均衡。

**当前工作区没有真实 72 产品表，默认文件是新规则的合成验证算例。** CP 暂保留 27 台、三个组各 9 台，路线/工时/计划逐条内容为占位。合成 MPS 的 PPN 使用 `PPNxx-1` 形式，flow 的 `PROD` 使用 `PPNxx`，用于验证 `-` 后厂家后缀忽略逻辑。验证结果不能作为现场生产承诺。真实表替换后重新运行 `python3 tools/build_data.py` 并重启服务；需要重建合成算例时运行 `python3 tools/build_case.py`。

规则 PPT 与重跑结果在 `output/`；旧算例与旧 PPT 已删除。

打开或刷新页面只读取当前保存的数据与配置，不自动排产。在“方案历史”可以直接打开此前保存的完整结果，无需重新计算。“重新排产”读取服务器已保存的数据；表单修改可“仅保存”或“保存并排产”。

1. “数据配置 → 1 数据来源”选择 .xlsx 和月份。文件上传后仍需保存，原文件不改写。
2. “2 设备与容量”核对 TYPE、EQPID、proberID、设备状态与 BAKE 腔体数；“3 停机与在制”核对 PM、借机及在制。编辑某表会自动勾选该表的手工覆盖。
3. “4 表与字段”直接填写 Sheet 名、表头行和字段映射，多个候选表头每行一个；保留高级 JSON。Oracle 入口移到“其他接口”，仍为预留。
4. “检查输入”只校验；“仅保存”保存有效输入并清除旧结果，不执行算法；“保存并排产”试排通过再保存并展示。检查通过不等于已完成可排性验证。
5. “恢复 Excel 设备与计划”清除设备、PM、借机、在制四类手工覆盖，校验后仅保存；保留 BAKE 容量和明确列出的手工 CP 调整。它不是恢复出厂设置。上传文件不会自动清除覆盖。
6. 查看 MPS 预测完成量及缺口，查看甘特资源占用；“数据配置”提供 MPS、排产和 PM 明细 CSV。
7. “排产诊断”查看异常和建议；错误面板会在支持的位置显示 Sheet、字段及输入记录序号，可跳转检查。输入记录序号不是 Excel 物理行号。
8. “方案历史”自动保存正式排产的完整输入和结果，列表展示最近 50 份，可打开或勾选两份比较。历史视图有明显标识，可导出；返回配置或重新排产时恢复当前工作，不覆盖服务器配置。

顶部“排产规则”是只读说明，关闭弹窗不触发排产。甘特图点击 CP 任务后，可在 Lot 详情选择“调整此工序”：指定机台、最早占用开始，或固定加工开始及当前针卡。调整先试排，成功才保存；在“停机与在制 → 手工 CP 调整”可解除。固定工序须满足前序工艺、设备资格、禁加工、换卡、PM、借机、在制等条件；无法满足时明确失败，不自动挪动指定时间。当前不支持拖拽排程、单独冻结 BAKE 批次或 QTIME。

手工调整绑定 Lot 行内容与工艺签名，重复 LotID 仍用 LotKey 区分。重导导致行顺序、Lot 内容或工艺变化时拒绝沿用旧调整，需要解除并重新选择。多条调整失效时可“解除全部并排产”；如仍有上传或配置草稿，先放弃草稿、解除旧调整，再重新导入。方案历史保存在配置文件同目录的 schedules/，诊断仍在 runs/；两者均不上传 GitHub。历史列表限制最近 50 份，不自动删除更早的磁盘文件。

Oracle 配置入口和适配器已预留，但尚未连接数据库。密码只配置环境变量名称。

数据读取或排产失败后，“数据配置”仍可用于重新上传、修改映射和修正配置。PM、借机及在制表支持与后端一致的日期格式；日期控件按北京时间展示，未修改的原始时间（含秒）在保存时保留。PM 指定时间重叠合并的业务规则不变。

BAKE 台数在 EQP 中有 OVEN 时取实际设备行数，每台腔体数采用生产配置中的值；没有 OVEN 时必须提供 BAKE 容量配置，不再隐式补出 7 台。当前腔体数为所有烤箱统一值，尚不支持每台烤箱分别设置。

配置草稿在本页打开期间保留，切换页面、查看预览或保存失败不会清空；有草稿时“重新排产”提示先保存或放弃修改。刷新或关闭页面时浏览器会提示，确认离开后草稿不保留。Oracle 设置需单独保存，新增计划需点击“添加计划并保存”；普通保存不会将它们误标为已提交。

数据预览每页 50 条，可翻页或输入页码，搜索和切表回到第一页；Sheet 名称匹配忽略大小写及全半角等格式差异。显示的是用于排产的有效输入，并注明 Excel 或手工覆盖来源；未映射表明确标为不参与排产。周目标单位为 wafer，负数、小数、空白及无效数字会拒绝导入，不再截断或静默补零。

甘特“全月”按实际月份绘制，包含 28、29、30 或 31 天。点击 PM 区间或“PM 执行对应关系”中的编号，可查看原始 PM、EQPID/proberID、实际停机资源及合并后的时间。Probe 与 EQP 是组合设备，任一部件维护都会整组停机；指定时间重叠时两项维护都保留，仅合并停机区间；不同时段则分别整组停机。连带停机不代表凭空新增另一部件的维护任务。

排产 CSV 增加 `LotKey`、资源释放时间及未排原因，没有工序的待排 Lot 也会列出；计算时间使用包含年份、秒和 `+08:00` 时区的格式。`LotKey` 仅对应本次输入行，重新导入后需核对。PM 对应明细 CSV 每条原始计划一行，以 `EventID` 对应实际维护；同一合并事件可能有多行，统计组合停机次数时按 `EventID` 去重。

```bash
python3 deploy.py check
python3 tools/check_fields.py
python3 -m unittest discover -s tests -v
node --test tests/frontend_state.test.js
python3 -m py_compile backend/server.py backend/server_core.py backend/data_sources.py backend/diagnostics.py backend/scheduler.py deployment/manage.py

```

Windows 可使用 `py -3 -m unittest discover -s tests -v`。部署进程身份检查用例为 `tests/test_deployment.py`；Windows 实机双击及 Linux systemd 安装仍需在目标环境验收。

排产规则回归为 `tests/test_scheduler.py`；全算例独立核验脚本为 `tools/verify_metrics.py`。迁移前后的详细对应关系见 [Python 统一改造说明](docs/technical/Python统一改造说明.md)。

当前是启发式原型，并非最优解求解器。现场上线前需完成认证授权、滚动快照、真实路线、日历、并发与安全加固；详见技术文档。
